# GoreeCloud Changelogs v1.0.0 — First Stable CLI/API Release

**Release type:** Source/package distribution. No production deployment is implied.

## Stable support boundary

The supported first stable scope is **the self-hosted Python 3.10+ command-line tool and locally bound, token-authenticated, read-only HTTP API**. Tested CI Python versions are 3.10, 3.11, 3.12 and 3.13 on Linux. The SQLite database stays on the selected host. This release does not introduce a remote service, hosted account, network gateway, or background synchronization.

The package has no third-party runtime dependencies. Source-build tools such as setuptools are build-time dependencies.

## Stable capabilities

- Create, inspect, edit and explicitly confirm deletion of detailed changelog entries for applications and services; filter and search by product, version and change kind
- Group entries into releases and render escaped Markdown or JSON release notes
- Complete-by-default Markdown or portable JSON export, bounded chunked exports and private no-clobber output files
- Preview-first, validated and transactional portable JSON import; optionally pin reviewed source bytes with SHA-256
- Consistent SQLite backups, source validation, opt-in guarded restore and pre-restore recovery snapshot
- Local database integrity and permission diagnostics
- **Loopback-only** HTTP API with bearer-token authentication, bounded request handling, exact continuation flags, and read-only endpoints:
  `GET /health`, `GET /v1/entries`, `GET /v1/entries/{id}`, `GET /v1/search`, `GET /v1/releases`, `GET /v1/summary`

## Explicitly not stable in v1.0.0

The optional `--web` browser viewer and `android-app/` native Android source remain **previews**, requiring actual-client privacy/accessibility acceptance. The Android app has no signed stable build. Neither preview is part of the v1.0.0 stable-support promise.

**No API writes, public HTTPS endpoint, GoreeCloud Identity integration, GoreeCloud Mesh synchronization or remotely accessible database** are provided. The CLI supports local database writes; that does not make the API writable.

## Installation

Download the release wheel from GitHub Releases and verify it against the attached `SHA256SUMS.txt`:

```sh
sha256sum -c SHA256SUMS.txt
python -m pip install goreecloud_changelogs-1.0.0-py3-none-any.whl
goree-changelogs --help
```

If using a Python virtual environment, install within that environment. The wheel filename is determined by build metadata; inspect the actual release assets rather than assuming an unrelated download is trustworthy.

## Basic local API

```sh
export GOREE_CHANGELOGS_API_TOKEN="$(python -c 'import secrets; print(secrets.token_urlsafe(48))')"
goree-changelogs serve --port 8765
```

Use `127.0.0.1` on the **same computer**, not `0.0.0.0`. Do not forward the API through a proxy or tunnel without a separately reviewed access-control and encryption design.

## Privacy and recovery responsibilities

Default SQLite data is **not application-level encrypted**. Protect it with OS ownership, ACLs, encrypted disks, private backup storage and tested recovery. Review backup retention. Restore replaces the selected live records; use `--dry-run` to validate a source, stop live writers, and use `--recovery-backup` when performing an explicitly authorized restoration. Never practice on irreplaceable databases.

## Release verification and limits

This tag is created only after the release-branch CI matrix, installed-wheel smoke checks and API process integration tests pass, and its commit matches the repository's main branch. Passing CI is not a substitute for target-host staging, ACL/encryption audit, power-loss recovery drill, monitoring/rollback assessment, or real-device preview testing.

Release artifacts are accompanied by SHA-256 checksums for integrity verification, **not** a cryptographic code-signature or independently audited software supply chain. Do not infer production deployment from source-release publication.
